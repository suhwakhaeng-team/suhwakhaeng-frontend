# 2차 UT · 조건부확률

## 참가자 흐름

로그아웃 화면의 **학습 체험하기** → `/ut` → 암호 `abcd` → `/ut2`.
기존 암호는 1차 UT로 이동한다. `/ut1`과 `/ut2` 직접 접속도 유지한다.

사전 13문항(개념 5개 × 2문항 + 기출형 3문항) → 오답/모름 개념 학습 → 기출 3문제 → 사후 13문항.
개념별 2문항 모두 정답이면 기초 학습을 생략하고 적용 문제를 우선 추천한다.
기출형 사전 오답을 우선 순위에 반영한다. 기출에서 막히면 미해결 하위 문제로 내려갔다 돌아온다.
설명 열람만으로 통과하지 않으며, 필수 취약 개념과 기출 3문제의 정답 제출 후에만 사후검사를 시작할 수 있다.

검사는 학습 예제/재시도 문제와 다른 숫자이며, 참가자를 A→B/B→A로 교차 배정한다.
수준/구조가 유사하도록 작성했지만 통계적으로 난이도가 동등하다는 검증까지 된 검사지가 아니다.
각 검사 중에는 정답·힌트를 제공하지 않는다. 서버가 채점하며 클라이언트는 점수를 제출하지 않는다.

## 기록과 관리자

- 별도 `ut2_participants` 테이블. UT1·실서비스 계정·태그 데이터에 쓰지 않는다.
- 참가자 토큰을 해시 저장하고 각 조회/제출에서 검증한다. 닉네임 중복은 허용한다.
- 사전/사후 응답, 모름, 문항별 활성 화면 시간, 학습 노드·변형·정오·시간을 저장한다.
- 설명을 보고 확인 문제를 제출한 학습 시간에는 설명을 읽은 시간도 포함한다. 탭을 숨긴 시간은 제외한다.
- 응답 유실은 동일 요청 키로 복구한다. 다른 탭 변경은 충돌 처리하고 미저장 답안을 보존한다.
- 관리자 **사용자 통계 → 2차 UT · 조건부확률** (`/admin/ut2`). 참가자 상세 및 `/admin/ut2.csv`.
- 개념/기출형 정답률, 변화(%p), 평균 시간, 모름을 분리한다. 미완료자를 0점이나 완료자 평균에 포함하지 않는다.
- 결과는 관찰된 전후 변화다. 대조군이 없는 UT만으로 서비스의 인과 효과를 확정하지 않는다.

## 운영 반영

프론트와 백엔드를 함께 배포해야 한다. 최신 소스의 `UT2_ENABLED` 기본값은 `true`, `UT2_PASSWORD` 기본값은 `abcd`.
기존 배포 환경이 `UT2_ENABLED=false`로 지정되어 있으면 변경 필요. 운영 MySQL의 `ddl-auto=update`는 새 테이블을 생성한다.
`validate`를 쓰는 환경은 아래 테이블 생성 스크립트를 별도 적용한 후 기동해야 한다. 기존 테이블/기록 삭제는 필요 없다.
프론트의 `/ut`, `/ut2`에 기존 SPA fallback 설정을 적용하고 `/api/v1/ut2/**`는 백엔드로 전달한다.
이 문서는 배포 준비 설명이며, 이번 구현 작업에서 운영 배포나 운영 DB 실행을 수행했다는 뜻은 아니다.

문제은행 원본: `src/routes/dev/ut2Assessment.ts` + `conditionalProblemBreakdown.ts`.
백엔드 사본: `src/main/resources/ut2/question-bank-v1.json`. 두 사본의 일치와 모든 수치 정답을 테스트한다.
진행 중 실험의 은행 v1을 수정하면 안 된다. 다음 실험에서는 버전/검사지를 새로 추가한다.
