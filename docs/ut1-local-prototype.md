# 중복조합 1차 UT · 로컬 프로토타입

서버 저장 버전은 `/ut1`이며 백엔드 관리자 리포트는 `/admin/ut1`입니다. 배포 설정/저장 범위는 [ut1-server.md](./ut1-server.md)를 참고하세요. 아래 설명과 `/dev/ut1`은 기존 로컬 시안에 관한 내용입니다.

- 실행: `npm run dev:graph`
- 학습: http://localhost:18085/dev/ut1
- 관리자 비교: http://localhost:18085/dev/ut1/admin
- 검증용 데모: 위 주소에 `?demo=1` 추가. 실제 UT 기록과 저장 키가 다릅니다.

기존 `MainLayout`, `HomeDashboard`, `CurriculumListSection`, `ProblemQuestionCard`, 동그라미 `ProblemLearningMap`을 재사용합니다. 기존 `/dev/problem-learning`과 실제 서비스 경로는 유지합니다. 프로토타입 경로는 개발 모드에서만 제공됩니다.

## 흐름

1. 로그인 화면의 개발 모드 전용 ‘학습 체험하기’ → 입장 암호 `1234` → 닉네임 입력 → 사전 테스트를 바로 시작합니다. 빈 닉네임은 허용하지 않습니다. 같은 닉네임도 별도 기록을 생성하며, 기존 기록은 삭제하지 않습니다. 페이지를 새로 열면 다시 암호를 입력하고 이 브라우저의 마지막 기록을 이어갈 수 있습니다. 실제 서비스 UID와 연결하지 않습니다.
2. 사전 테스트: 곱의 법칙·팩토리얼·순열·조합·중복조합 각 2문항, 총 10문항. 숫자 입력과 ‘모르겠습니다’. 최초 답안만 저장하며 테스트 중 해설·힌트·정오답을 보여주지 않습니다. 비교를 위해 prune하지 않습니다.
3. 사전 결과로 기초 시작점을 정합니다. 개념별 2/2 정답이면 해당 개념·기초 확인을 건너뛰고, 0/2·1/2(오답·모름 포함)이면 개념 설명·활동 → 숫자 확인 문제 → AN 적용 확인 순으로 보충합니다. 전부 모르면 곱의 법칙 → 팩토리얼 → 순열 → 조합 → 중복조합을 먼저 확인한 뒤 BN으로 갑니다. 학습 중 확인한 기초는 다음 목표에서 반복하지 않습니다. 문서 `중복조합_중급문제5선_v2.docx`의 5개 목표 문제 첫 답은 45, 28, 120, 36, 6입니다. 원래 수학적 조건을 유지하고 표현을 정리했습니다. 학습용 AN·개념 확인 문항은 별도 작성한 보충 문제이며 실제 문제은행 ID가 없습니다.
4. BN에서 막히면 AN → 개념 설명과 간단한 조작 활동 → 숫자를 바꾼 확인 문제 → AN/BN 재도전으로 복귀합니다. 하위 문제 정답으로 상위 문제를 자동 통과시키지 않습니다. 숫자 변형의 정답은 매번 계산합니다. 정해진 유한 범위의 변형을 순환하므로 무한히 고유한 문항은 아닙니다.
   학습 문제 정답 시 지도로 바로 전환해 통과한 노드를 초록색으로 표시합니다. 지도에서 다음 문제/개념 버튼을 누른 뒤에만 학습을 이어가며, 마지막 목표 정답은 지도 확인 후 완료 기록으로 보관합니다. 사전/사후 테스트는 정답 피드백 없이 기존대로 진행합니다. 참가자 화면의 개발 안내 문구와 관리자 링크는 제거했고, 관리자 페이지는 별도 주소로 유지합니다.
5. 목표 5개를 직접 해결하면 사후 테스트를 엽니다. 동일 유형의 다른 숫자 10문항입니다.
6. 결과에서 전후 정확도, 개념별 정답 수, 평균 시간, 정확도 차이(%p)를 비교합니다. 관리자는 문항별 문제·숫자·입력 답안·정답·정오답/모름·시간 및 학습 경로를 볼 수 있습니다. 사후 미완료는 0점이나 0%p가 아니라 미완료로 표시합니다.

순열을 모든 중복조합 문제의 직접 선수조건으로 연결하지 않습니다. 다섯 개념을 확인하는 것은 이 UT의 학습 범위이며, 미확인 기초를 보충하는 동안에는 해당 기초 확인 가지도 지도에 함께 표시합니다. 확인이 끝나면 목표에 필요한 개념과 전용 AN 중심으로 표시합니다. 기존 BN-first 진행 기록은 학습 이력·사전 답안·완료 목표를 지우지 않고, 미확인 기초가 있으면 그중 가장 이른 곳에서 이어갑니다.

## 개념 학습 활동

`UT1ConceptActivities.tsx`와 `ut1ConceptActivityModel.ts`가 활동 화면과 계산을 담당합니다. 교재는 원리와 개념 순서만 참고하며, 교재 이미지/본문을 참가자 화면에 옮기지 않습니다. 기존 사전/사후 테스트, 저장 스키마, 문제 지도, 노드 ID와 점수 계산은 유지합니다.

- 곱의 법칙: 옷차림 예상 → 여섯 조합 직접 만들기 → 표를 곱셈 식으로 연결 → 선택지 증가와 세 단계 선택 확인.
- 팩토리얼: 세 사람의 모든 배열을 만들고 → 네 자리의 남은 선택지 곱셈 → 팩토리얼 의미 → 다른 숫자 독립 연습.
- 순열: 두 역할의 모든 배치를 만들고 → 필요한 자리까지만 곱하기 → 역할/순서 구별 → 독립 연습.
- 조합: 역할 없는 팀을 만들고 → 구성원이 같은 배열을 직접 묶기 → `r!`로 나누는 이유 → 독립 연습.
- 중복조합: 빈 상자를 포함한 서로 다른 공 배분 → 공과 칸막이 위치의 일대일 대응 → 칸막이 위치를 조합으로 세기 → 독립 연습.
- 최솟값: 서로 다른 최솟값 `[1,3,0]`을 먼저 넣고 → 남은 공만 배분 → 원래 개수와 남은 개수 연결 → 다른 조건 독립 연습. 최솟값의 합이 상자 수와 다르게 설정되어 상자 수만 빼는 오개념을 구별합니다.

단계는 예상하기/직접 만들기/규칙 찾기/혼자 풀기입니다. 활동은 클릭/키보드로 조작하고, 활동 내부 오답은 해설과 숫자가 바뀐 연습으로 이어집니다. 활동 완료는 **확인 문제 버튼을 열기만** 합니다. 실제 숫자 확인 문제를 맞혀야 기존 채점/기록 흐름으로 통과 지도에 들어갑니다. 활동 내부 응답은 사전/사후 점수와 UT 최초 답안에 섞지 않습니다. 활동 중 홈/지도로 나가거나 새로고침하면 그 활동은 처음부터 다시 시작하며, 이미 제출한 테스트/확인 답안과 학습 기록은 보존합니다.

## 목표별 AN

공통 개념과 기초 AN은 재사용하되, BN의 적용 단계를 확인하는 AN은 목표마다 별도 3개씩 둡니다. 기존 `a-model`, `a-minimum` 등은 과거 기록 호환을 위해 계산/ID를 보존합니다. 새 AN은 `a-g1-*`부터 `a-g5-*`까지 별도 ID로 기록하여 다른 목표의 AN 정답이 새 AN의 통과로 표시되지 않습니다.

| 목표 | 전용 AN |
| --- | --- |
| 음이 아닌 정수해 | 0도 가능한 정수해 / 정수해를 별과 칸막이로 / 칸막이 자리 고르기 |
| 최솟값이 다른 정수해 | 서로 다른 최솟값 더하기 / 최솟값을 빼서 식 바꾸기 / 바꾼 식의 정수해 세기 |
| 빈 상자도 가능한 배분 | 상자 수에서 칸막이 수로 / 빈 상자가 있는 배치 읽기 / 네 상자의 배분 세기 |
| 각 상자에 하나 이상 | 각 상자에 하나씩 먼저 넣기 / 남은 공만 자유롭게 배분하기 / 남은 공의 배분 경우 세기 |
| 조건에 맞게 볼펜 고르기 | 색별 필수 개수 먼저 고르기 / 필수 조건 없는 색 확인하기 / 추가 볼펜을 중복해서 고르기 |

모든 AN을 강제로 먼저 풀게 하는 대신, 기존대로 BN에서 막혔을 때 필요한 AN으로 내려갑니다. 이미 통과한 공통 개념/기초는 목표가 바뀌었다는 이유로 반복하지 않습니다. 전용 AN의 선수 조건을 모두 확인했는데도 틀린 경우는 해당 AN의 풀이를 보여주고 숫자를 바꿔 재도전합니다. 아직 배우지 않은 개념이 필요하면 기존 개념 활동으로 내려갑니다. 사전/사후 문제와 시간·성적 비교는 변경하지 않습니다.

기초 확인이 끝난 목표 지도는 개념/AN/BN의 세 열로 배치합니다. AN 세 개는 같은 열에서 균등 간격, BN과 개념 묶음은 AN 묶음의 중심선에 맞춥니다. 미완료 기초나 기존 진행 가지가 추가되면 사용하지 않는 열을 압축하되 연결·문항·기록은 변경하지 않습니다. 통과 애니메이션에서도 원의 가로 중심점을 유지합니다.

## 기록과 측정의 한계

- `localStorage`의 `suhwakhaeng:ut1:local:v1` 키에 보관합니다. 데모는 `:demo` 접미사로 분리됩니다. 다른 기기/브라우저와 공유되지 않으며 브라우저 데이터 삭제 시 기록도 사라집니다.
- 실제 계정, 기존 진단/학습 기록, API, 운영 DB를 변경하지 않습니다. 관리자 페이지는 **백엔드 페이지의 로컬 시안**이며 서버 저장/인증 구현이 아닙니다.
- 입장 암호는 로컬 화면 전환 확인용으로 프론트에서 검사합니다. 보안/인증 수단이 아니며 관리자 주소도 보호하지 않습니다. 실제 배포 전 서버 암호 검증, 요청 제한, 참가자 세션과 관리자 인증을 구현해야 합니다. 암호를 저장소에 보관하지 않습니다.
- 사전/사후 풀이 시간은 해당 문제 화면의 활성 시간입니다. 숨긴 탭, 홈, 지도, 개념 설명은 제외합니다. 2초마다 중간 시간 스냅샷을 저장하고 새로고침 후 이어 풉니다. 강제 종료 등에서는 마지막 저장 이후 최대 약 2초가 빠질 수 있습니다. 학습 확인 문제 시간은 같은 방문 중 홈/지도/설명 시간을 제외하지만, 미제출 학습 문제의 시간은 새로고침 후 새로 측정합니다.
- A→B와 B→A를 같은 브라우저에서 참가자 생성 순서에 따라 교대합니다. 계산 크기가 완전히 같은 난이도라고 검증한 문제지는 아닙니다. 참가자 수가 적으면 유형/숫자 효과가 섞일 수 있습니다.
- 정답률은 테스트 10문항 기준이며 ‘모르겠습니다’도 오답에 포함하되 따로 집계합니다. 예: 30%→70%는 **+40%p**입니다. 평균 변화는 전후 완료자만 사용합니다.
- 같은 유형에서의 변화이며 학습 효과 전체/인과 효과를 입증하는 수치가 아닙니다. 교수님 발표용 실제 UT를 진행하려면 문항 검토, 서버 저장, 참가자 식별, 관리자 접근 분리를 추가해야 합니다.
- 테스트/학습 중 같은 기록을 여러 탭에서 동시에 수정하는 방식은 지원하지 않습니다. 관리자 시안은 읽기 전용이며 다른 탭의 저장 이벤트를 반영합니다. 데모 검증은 정상 UT 기록과 분리됩니다.
