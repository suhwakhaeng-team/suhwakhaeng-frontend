# 1차 UT 서버 연결

## 참가자와 관리자

- `/ut1`: 서버 저장 버전. 입장 암호 → 닉네임 → 사전 검사 → 학습 → 사후 검사. 기존 웹 디자인과 문제 지도/학습 흐름을 재사용한다.
- 백엔드 `/admin/ut1`: 참가자 목록, 전후 정답률, 변화(%p), 평균 풀이 시간, 모름 응답. 기존 관리자 Basic 인증을 사용한다.
- 백엔드 `/admin/ut1/{참가자 UUID}`: 문항별 전후 답안/정답/판정/시간, AN·BN·개념 확인 문제 학습 경로.
- 백엔드 `/admin/ut1.csv`: 제출 답안 전체 CSV. 참가자 인증 키는 포함하지 않는다.
- 기존 `/dev/ut1`와 `/dev/ut1/admin`은 로컬 전용 시안이다. 이곳의 과거 기록을 자동 업로드하거나 삭제하지 않는다.

닉네임은 표시용이며 고유 식별자가 아니다. 같은 닉네임도 참가자 UUID로 구분한다. 기존 서비스 계정/UID/진단/학습 테이블과 연결하지 않는다. A→B/B→A는 서버 참가자 생성 순서에 따라 교대한다.

## 배포 시 필요한 설정 (아직 배포하지 않음)

1. 백엔드에 추가된 `ut1_participants` 테이블을 준비한다. 운영 환경이 자동 스키마 변경을 사용하지 않으면 `suhwakhaeng-backend/scripts/migrations/20261002_ut1_participants.sql`을 실행한다. 기존 테이블은 변경하지 않는다.
2. 운영 백엔드는 기존 MySQL을 사용하는 `prod` 프로필로 배포한다. `UT1_ENABLED=true`로 UT API와 리포트를 켠다. 입장 암호는 `UT1_PASSWORD=1234`이며, 미지정 기본값도 1234다. `mock` 프로필은 관리자 인증을 생략하고 H2가 종료 시 지워지므로 실제 UT 배포에 사용하면 안 된다.
3. 프론트 빌드에 `VITE_UT1_ENABLED=true`를 설정하면 로그인 화면에 ‘학습 체험하기’ 버튼이 나타난다. `/ut1` 경로 자체는 일반 빌드에도 포함된다. 개발용 다른 `/dev/*` 페이지를 운영에 노출하지 않는다.
4. 운영 프론트는 기존 same-origin `/api/v1` 프록시를 사용한다. 별도 서버 환경변수/토큰 리프레시를 사용하는 기존 계정 API와 분리되어 있다. 로컬에서는 `VITE_UT1_API_BASE_URL=http://127.0.0.1:18086/api/v1`처럼 **로컬 테스트 서버**를 명시하거나 Vite `/api` 프록시(기본 localhost:8080)를 사용한다. 운영 문제은행 조회용 `VITE_API_BASE_URL`로 UT 쓰기를 보내지 않는다.
5. 배포 후 별도 테스트 참가자로 입장·답 제출·새로고침·이어하기와 실제 관리자 `/admin/ut1` 리포트·CSV를 확인한다. Git push만으로 DB/서버 설정까지 적용되었다고 보지 않는다.

## 저장과 보안

입장 암호는 서버가 검사한다. 이것은 UT 입장용 공유 암호이며 관리자 권한이 아니다. 참가자마다 브라우저에서 암호학적으로 무작위인 키를 생성하고 서버에는 SHA-256 해시만 저장한다. 본인 기록 조회/저장은 `X-UT-Token` 키가 필요하다. 공개 참가자 목록 API는 없다. 관리자 보고서와 CSV는 기존 `/admin/**` 인증으로 보호된다. 운영은 HTTPS를 사용한다.

정답은 서버의 버전 고정 문제은행으로 검산한다. 숫자 변경 범위는 기존 프론트와 동일하다. 전후 검사 답안과 학습 경로는 append-only이며 최초 답안을 지우거나 바꿀 수 없다. 참가자 기록의 revision으로 여러 탭의 덮어쓰기를 막는다. 생성·동일 저장 재시도는 중복 기록을 만들지 않는다.

참가자 화면은 서버 저장 실패를 알리고 이 기기에 복구본을 남긴다. 수동 ‘다시 저장’과 같은 기기의 ‘이어하기’를 지원한다. 브라우저 저장 키는 `suhwakhaeng:ut1:server:v1`로 기존 로컬 시안과 분리한다. 암호는 저장하지 않으며 참가자 인증 키는 복구를 위해 이 기기에 보관한다. 다른 기기에서는 키 없이 같은 닉네임만으로 이전 참가자 기록을 이어갈 수 없다.

시간은 클라이언트가 측정한 활성 문항 시간이다. 서버 시계로 독립 측정한 시간이 아니며, 숨긴 탭·홈·지도·개념 활동 시간은 제외한다. 미제출 검사 시간은 약 2초마다 스냅샷을 저장한다. 네트워크/프로세스 종료 상황에 따라 마지막 미저장 구간이 빠질 수 있다. 개념 활동 내부 클릭·연습은 기존처럼 점수/제출 경로에 넣지 않는다.

입장 시도 제한은 백엔드 프로세스별/접속 IP별 분당 60회다. 프록시 환경에서 같은 IP로 보일 수 있으므로 대규모 운영에서는 신뢰하는 프록시 IP 구성과 분산 제한으로 보강한다. 기존 관리자 계정/암호는 변경하지 않았으며 실제 운영 접근 관리 정책을 별도로 점검한다.

## 검증

- 프론트: `node --test tests/ut1Server.test.mjs tests/ut1ConceptActivity.test.mjs tests/ut1Entry.test.mjs tests/ut1.test.mjs tests/problemLearning.test.mjs tests/problemLearningRealBank.test.mjs tests/levelTestPreview.test.mjs`
- 백엔드: `gradlew test --tests '*Ut1IntegrationTest' --tests '*AdminStatisticsControllerTest'`
- `tests/ut1Server.test.mjs`는 백엔드 버전 고정 문제은행과 모든 프론트 변형을 대조한다. 문항을 수정할 때 서버 문제은행도 함께 갱신하여 이 테스트를 통과시킨다.

정답률은 10문항 기준이며 모름을 오답에 포함하고 별도 집계한다. 미완료 검사 정답률은 빈 값이다. 평균 성적 변화는 전후 검사 완료자만 사용하고, 30%→70%는 +40%p다. 숫자가 다른 동일 유형의 검사 결과이며 이 수치만으로 학습의 인과 효과를 입증하지 않는다.
